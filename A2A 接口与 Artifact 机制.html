Part 1 · A2A 接口规范（关键接口）

agent-card / message:send / message:stream / get task / cancel task —— 暂定只提供这 5 个接口，其他 A2A 接口有需要再行添加

本版为 Project AI Data Hub 与 Data Agent 集成时需要用到的关键接口。其他标准能力（task list、push notification、extended agent card、错误码、认证细节、streaming event 完整格式等）建议直接参考 A2A 官方协议，不在当前实施阶段重复定义。

实施阶段需对齐以下 5 个关键接口：

2. Send Message

Purpose：Business Agent 向 Data Agent 发起一次业务问题请求。Data Agent 可以直接返回回答，也可以返回 task，由 Business Agent 后续查询或通过 streaming 接收结果。

API：

POST /message:send
Content-Type: application/a2a+json
Authorization: Bearer <token>

Request example：

{
  "message": {
    "role": "ROLE_USER",
    "parts": [
      { "text": "Lenovo Legion Go Charging Connector with Battery for Controllers 可以卖美国吗？请返回可销售 PN、description 和 EAN/UPC/JAN code。" }
    ],
    "metadata": {
      "requestId": "req-pd-poc-001",
      "callerAgent": "AI Data Hub Business Agent",
      "endUser": "user001",
      "tenantId": "project-ai-data-hub",
      "businessDomain": "PC Accessories",
      "businessContext": {
        "scenario": "product information inquiry",
        "targetCountry": "US",
        "productCategory": "Accessories"
      },
      "outputMode": "interpreted_answer_with_evidence"
    }
  }
}

Response example：

{
  "task": {
    "id": "task-pd-poc-001",
    "contextId": "ctx-pd-poc-001",
    "status": { "state": "TASK_STATE_COMPLETED" },
    "artifacts": [
      {
        "name": "answer",
        "parts": [
          { "text": "该产品可以在美国销售。可销售 PN 包括 GXH1Q27134，description 为 Charging Connector-US/CA。相关 EAN/UPC/JAN 信息见返回数据明细。" }
        ],
        "metadata": {
          "evidence": [
            { "source": "Product MDM / LOIS", "dataObject": "Accessories product information", "fields": ["PN", "description", "EAN/UPC/JAN", "support country"] }
          ],
          "policyChecked": true,
          "auditId": "audit-pd-poc-001"
        }
      }
    ]
  }
}

3. Send Streaming Message

Purpose：用于处理时间较长的问题（兼容性、库存、shipment 分析、跨数据源组合回答）。Business Agent 发起后，Data Agent 通过 streaming 返回 task 状态、中间结果和最终回答。

API：

POST /message:stream
Content-Type: application/a2a+json
Authorization: Bearer <token>
Accept: text/event-stream

Request example：

{
  "message": {
    "role": "ROLE_USER",
    "parts": [
      { "text": "XX 产品兼容哪些设备？如果有 conditional support，请带出 footnote。" }
    ],
    "metadata": {
      "requestId": "req-pd-poc-002",
      "callerAgent": "AI Data Hub Business Agent",
      "endUser": "user001",
      "tenantId": "project-ai-data-hub",
      "businessDomain": "PC Accessories",
      "businessContext": { "scenario": "compatibility inquiry", "dataObject": "Compatibility" },
      "outputMode": "interpreted_answer_with_evidence"
    }
  }
}

Streaming event example：

{
  "task": { "id": "task-pd-poc-002", "status": { "state": "TASK_STATE_WORKING" } }
}

Final event example：

{
  "message": {
    "role": "ROLE_AGENT",
    "parts": [
      { "text": "该产品支持 AA 机型；部分设备为 conditional support，具体限制请参考 footnote。" }
    ],
    "metadata": {
      "evidence": [
        { "source": "OCM", "dataObject": "Compatibility", "fields": ["support status", "device model", "footnote"] }
      ],
      "policyChecked": true,
      "auditId": "audit-pd-poc-002"
    }
  }
}

4. Get Task

Purpose：Business Agent 查询某个 task 的当前状态和结果。适用于 message:send 返回异步 task 后，Business Agent 后续轮询结果。

API：

GET /tasks/{taskId}
Authorization: Bearer <token>

Response example：

{
  "id": "task-pd-poc-003",
  "contextId": "ctx-pd-poc-003",
  "status": { "state": "TASK_STATE_COMPLETED" },
  "artifacts": [
    {
      "name": "answer",
      "parts": [
        { "text": "该产品当前在欧洲可用库存为 1,200 件，其中 Lenovo warehouse 800 件，Vendor VMI 400 件。" }
      ],
      "metadata": {
        "evidence": [
          { "source": "SCC / S4", "dataObject": "Accessories Stock Data", "fields": ["stock quantity", "storage location", "stock type"] }
        ],
        "policyChecked": true,
        "auditId": "audit-pd-poc-003"
      }
    }
  ]
}

5. Cancel Task

Purpose：Business Agent 取消仍在执行中的 task（例如用户中断较长时间的 shipment 分析或库存查询）。

API：

POST /tasks/{taskId}:cancel
Authorization: Bearer <token>

Response example：

{
  "id": "task-pd-poc-004",
  "status": { "state": "TASK_STATE_CANCELED" }
}

Part 2 · A2A Artifact 机制（调用方指南）

大结果集不内联返回，通过 evidence + artifact_id 引用，调用方分页取回 —— 回答“给业务 agent 提供什么数据格式”的正式方案

适用对象: 通过 A2A 协议调用 GDA agent 的集成方（其他 agent / 平台 / 外部系统） 协议版本: A2A 1.0

1. 什么是 Artifact

当查询返回大量数据时，完整结果不会内联在响应里，而是被保存在服务端（称为 artifact）。响应中只返回数据引用（evidence，含 artifact_id），调用方需要时再通过分页接口取回完整数据。

这样做的好处：

  • 响应轻量、快速返回
  • 不会因大结果导致响应超时或传输失败
  • 调用方按需取数，不用强制接收全量

2. 如何获取数据

第 1 步：发送查询

POST /a2a/message:send          （同步）
POST /a2a/message:stream        （流式）

请求头：

Header 值
Content-Type application/a2a+json
A2A-Version 1.0
Authorization Bearer <API key>（需 agent:chat scope）

请求体：

{
  "message": { "role": "user", "parts": [{ "text": "查询...", }] },
  "context": { "target_agent_id": "<agentId>", "output_mode": "interpreted" }
}

第 2 步：从响应中取 artifact_id

完成响应（kind: "completed"）的结构：

{
  "kind": "completed",
  "task_id": "task_8b0529e7",
  "interpreted_answer": {
    "summary": "查询结果摘要...",
    "evidence": [
      {
        "source": "metric view: magellanedw.dwd_prd.product_master_metric_view",
        "row_count": 500,
        "freshness": "2026-08-03",
        "artifact_id": "art_task_8b0529e7_metric_magellanedw_dwd_prd_product_master_metric_view"
      }
    ]
  }
}

evidence[] 里每项对应一次数据查询，artifact_id 就是取数的钥匙。

第 3 步：分页取回完整数据

GET /a2a/artifacts/:artifact_id?page=N&page_size=M

查询参数：

参数 默认 说明
page 1 页码（从 1 开始）
page_size 100 每页行数（上限 500）

响应：

{
  "artifact_id": "art_task_...",
  "source": "metric view: ...",
  "command": "run: metric ...",
  "columns": ["product_no", "product_nm"],
  "rows": [
    ["5M51D20897", "MOUSE 400 USB-C Compact WL MS"],
    ["5M51D20903", "MOUSE 400 USB-C wired MS"]
  ],
  "page": 1,
  "page_size": 100,
  "total_rows": 500,
  "expires_at": "2026-08-04T15:00:00Z"
}

分页方式：rows 是 (string|null)[][] 二维数组，与 columns 对齐。翻页只需递增 page，直到取满 total_rows。

3. 生命周期与限制

项 说明
有效期 artifact 保存 24 小时（见 expires_at），过期后返回 artifact_not_found
行数上限 最多存 500 行（row_count 可能更大，表示总命中数，超出的部分需缩小查询重取）
数据格式 仅支持表格格式输出；非表格结果 rows 为空（columns 可能为空）
租户隔离 artifact 只对同一租户的 API key 可见

4. 错误处理

HTTP code 场景
401 invalid_api_key API key 无效/过期
403 insufficient_scopes 缺 agent:chat scope
404 artifact_not_found artifact 不存在/已过期/无权限
400 invalid_request 请求体不合法

建议：取数时先检查 expires_at；取到 artifact_not_found 时，用 statement_id（若提供）或重新查询获取数据。

5. 完整示例（curl）

# 1) 发送查询
curl -X POST https://<host>/a2a/message:send \
  -H "Content-Type: application/a2a+json" \
  -H "A2A-Version: 1.0" \
  -H "Authorization: Bearer gda_sk_..." \
  -d '{
    "message": { "role": "user", "parts": [{ "text": "查询在售鼠标的 PN 明细" }] },
    "context": { "target_agent_id": "<agentId>", "output_mode": "interpreted" }
  }'
# → 响应中 evidence[].artifact_id

# 2) 分页取数（第 1 页, 每页 100 行）
curl -X GET "https://<host>/a2a/artifacts/<artifact_id>?page=1&page_size=100" \
  -H "Content-Type: application/a2a+json" \
  -H "A2A-Version: 1.0" \
  -H "Authorization: Bearer gda_sk_..."

6. 对接清单

  1. 申请 API key（agent:read + agent:chat scopes）
  2. 发送查询 → 解析 interpreted_answer.evidence[]
  3. 对每个 artifact_id 分页取数（直到 page * page_size >= total_rows）
  4. 处理过期（24h 内取完，或按需重新查询）
